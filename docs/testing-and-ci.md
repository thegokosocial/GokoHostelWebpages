# Tests and CI

Numeric-input regression coverage verifies that editable `type="number"` controls store `event.target.value` as a string. Conversion with `Number`, parsing, clamping, or zero fallbacks belongs at calculation and submission boundaries so clearing a controlled input does not immediately render `0`.

**Git-safe.**

```bash
npm test              # vitest run — does **not** typecheck
npm run test:watch
npm run lint
npx tsc --noEmit      # required before push; Vitest missed `mode` used-before-assigned
npm run build         # Next CI build — NOT the Worker
npm run test:e2e      # Playwright browser regression suite (requires local loopback)
```

CI (`.github/workflows/ci.yml`): push/PR to `main` → `npm ci` → test → lint → `next build` → `npm audit --audit-level=high || true`. **Does not deploy.** Node 20.

## Regression coverage policy

Every behavior, page, API, schema, auth, permission, or workflow change adds or updates a focused regression test in the same turn. Extend an existing suite before creating a new one.

| Layer | Use it for |
|---|---|
| Vitest | Pure logic, parsers, money/date rules, permissions, API routes, error contracts, retries, idempotency, and disposable-database workflows |
| Playwright | Critical navigation and cross-component journeys, responsive behavior, and user-visible loading/empty/unauthorized states |
| Build/type/lint | Compile-time and framework integration safety |

Playwright uses deterministic mocked APIs by default. It must not use production credentials or live mutable data. Pure logic does not need a browser test when the relevant behavior is already covered at the Vitest/API layer.

High-risk coverage priorities are auth/RBAC, bookings and payments, guest booking/self-check-in, food and kitchen workflows, CMS/public rendering, Aiosell/channel-manager sync, failover, and error/retry/idempotency behavior.

The Playwright suites sign into mocked sessions or use public pages with deterministic API behavior. They do not use production credentials or mutate a live database. `e2e/admin-navigation.spec.ts` covers mobile navigation, desktop top-level pages, every Management tab, nested Food Settings tabs, Food Settings Save All success feedback and clean-state transition, selected in-page controls, and Admin Food Orders edit journeys for explicit cancellation before changes, repeated served-order quantity changes, partial/paid states, one final save batch, and stable mobile action-row layout. `e2e/public-navigation.spec.ts` smoke-tests the public marketing route set and a representative homepage navigation link.

Any dynamic D1/SQLite `IN (...)` lookup must use `src/lib/dbBatch.ts` (`collectInBatches` / `uniqueInBatches`). The shared 25-ID ceiling leaves room for fixed predicates and multiple `IN` lists in one statement. Bulk-query regression tests must exercise the exact boundary and at least one multi-batch input (25/26 or 51 IDs), because small fixtures and mocked route helpers cannot detect production parameter-limit failures. Query helpers should be tested at the shared database layer, not only through a route mock.

`src/__tests__/admin-surface-contract.test.ts` is the Admin inventory guard: it checks that every top-level Admin section is permission-mapped and rendered, every Management tab has an access gate and render branch, every Admin API route authenticates, and every Admin route is listed in `docs/api-map.md`. `src/__tests__/admin-route-smoke.test.ts` dynamically discovers every POST Admin route and action and sends it through the real authentication boundary; this currently exercises 295 route/action cases and fails when a new action can reach application/database code without authentication. Use [admin-regression-matrix.md](admin-regression-matrix.md) to select focused behavior tests when adding or changing a page/action; the contract and smoke tests are drift/auth guards, not substitutes for success, validation, authorization, duplicate, audit, and failure tests for each mutation.

**Cloudflare Workers Builds** (dashboard, worker `goko-hostel-latest-webpage`) **does** ship: push to `main` → `npm run cf:build` → `npx wrangler deploy`. That build runs Next typecheck. `let mode: string` without an initializer in `push-inventory/route.ts` failed build `4e62b55a` (commit `5b466f0`) with `Variable 'mode' is used before being assigned`. Initialize (`= "full"`) so control-flow always assigns before the empty-updates return. Same `tsc` pass also needs `realignAssignments` dates narrowed (`if (moveDates && newCheckin && newCheckout)`) and calendar `onAction` as `Promise<boolean | void>`.

Cloudflare production builds also run `npm run db:verify:prod` before compiling. This is intentionally separate from local migration tests: local/disposable D1 proves SQL correctness, while the release gate proves the remote migration ledger is caught up. If D1 is unavailable or migrations are pending, the Worker build fails closed.

Dependency security checks use `npm audit`. Next stays on the supported 15.5 patch line; its private PostCSS copy is overridden to the audited patched release. SheetJS is pinned to the official patched `cdn.sheetjs.com` distribution because the abandoned npm-registry `xlsx` package has no repaired release. Keep the existing authenticated 5 MB / 500-row import limits when updating spreadsheet parsing.
